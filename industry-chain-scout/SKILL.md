# 产业链投研（Industry Chain Scout）

## 概述

本技能用于对一个投资主题进行全产业链扫描，回答三个递进问题：

1. **环节梳理（What）**：产业链由哪些环节组成？每个环节是什么？
2. **受益逻辑（Why）**：每个环节为什么受益？传导路径、确定性、弹性如何？
3. **上市公司（Who）**：每个环节有哪些上市公司？估值是否匹配？

最终产出一份主报告，包含估值数据表和潜在预期差标的筛选。

## 触发条件

当用户提出以下类型的需求时，触发本技能：

- 对某个产业/主题进行投资机会扫描
- 梳理某个产业链的上下游环节
- 寻找某个投资方向的受益标的
- 评估某个产业链各环节的受益确定性和估值匹配度
- 类似表达："帮我看看XX产业链"、"XX有哪些投资标的"

## 工作流程

### Step 0：明确研究主题与初始化文件夹

**目标**：确认用户要研究的产业链主题，划定边界。新建文件夹。

**操作**：

1. 从用户输入中提取研究主题（如"AI数据中心上游"、"固态电池"、"人形机器人"等）
2. 确认研究的范围边界：
   - 全产业链 or 特定环节？
   - A股/港股/美股 or 全市场？
   - 是否有特定关注点（如"只看国产替代"、"只看上游"）？
3. 如果用户未明确指定，默认：
   - 全产业链扫描
   - A股为主，港股/美股覆盖关键标的
   - 关注所有受益环节

**输出**：新建文件夹：`./[主题]`，后续步骤所有文件都放在该文件夹中。

---

### Step 1：环节梳理报告（What）

**目标**：全面梳理产业链的各环节，回答"这个产业链由什么组成"。

**操作**：

#### 1.1 广泛搜索收集信息

使用金融相关skill和进行多轮搜索：

- 中文搜索："[主题]产业链"、"[主题]上游"、"[主题]价值量排序"、"[主题]市场空间"
- 英文搜索："[topic] value chain"、" [topic] upstream supply chain"、"[topic] market size"
- 研报搜索："[主题]券商研报"、"[主题]行业深度"
- 搜索引用券商研报中的数据（如中信建投、华泰证券、东吴证券等）

#### 1.2 产业链拆分

将产业链拆分为**大类**，每个大类下包含**子环节**。拆分原则：

- **独立性(Independence)**： 所有大类互相独立不交叉
- **完备性(Completeness)**： 所有大类加总覆盖到整个产业链
- **有效性(Validity)**： 所有环节具备一定市场规模

#### 1.3 每个环节描述

对每个子环节，描述以下要素：

| 要素 | 说明 |
|------|------|
| 定义 | 一句话说明这是什么，要通俗易懂 |
| 在产业链中的角色 | 该环节服务于产业链的哪个功能 |
| 技术趋势 | 是否存在技术换代、规格升级、范式转换 |
| 市场规模 | 当前规模及预测（标注来源） |
| 关键瓶颈 | 供给约束、技术壁垒、产能瓶颈等 |

#### 1.4 绘制产业链全景图

用 ASCII art 绘制产业链各环节之间的关系图，展示上下游连接和核心流向。

**输出文件**：`环节梳理.md`

---

### Step 2：受益逻辑报告（Why）

**目标**：分析每个环节的受益逻辑，回答"为什么受益、确定性如何、弹性多大"。

**操作**：

#### 2.1 分析传导路径

对每个子环节，画出从"需求驱动"到"环节受益"的传导路径：

```
[初始需求] → [传导层1] → [传导层2] → ... → [目标环节受益]
```

标注：
- 传导层数（越少越直接）
- 每层的传导机制

#### 2.2 六维度评估

对每个子环节进行六维度评估：

| 维度 | 说明 | 评级 |
|------|------|------|
| **确定性** | 受益的确定程度（法规强制/技术必然 vs 间接/或有） | ⭐1-5 |
| **弹性** | 量增/价增/量价双击的弹性大小 | ⭐1-5 |
| **持续性** | 受益逻辑可持续的时间长度 | ⭐1-5 |
| **竞争格局** | 供给端竞争格局的优劣（寡头/双寡头 > 分散） | ⭐1-5 |
| **估值匹配度** | 当前估值是否充分反映了受益逻辑 | ⭐1-5 |
| **综合排序** | 确定性×弹性×估值匹配度 | 排名 |

**估值匹配度特别说明**：
- ⭐5 = 估值尚未反映受益逻辑（预期差大）
- ⭐3 = 部分反映
- ⭐1 = 估值已充分甚至过度反映

#### 2.3 驱动因素分类

对每个环节标注驱动因素类型：
- 🔴 **强驱动**：技术换代/规格升级/法规强制/供给制约
- 🟢 **量增驱动**：随行业规模扩张量增
- 🟡 **弱驱动/待验证**：技术路线未确定/渗透率低
- ⚠️ **替代风险**：存在被新技术替代的可能

#### 2.4 综合评分表

将所有环节的六维度评分汇总为一张表，按综合排序排列。

**输出文件**：`环节受益逻辑.md`

---

### Step 3：上市公司估值报告（Who）

**目标**：梳理每个环节的上市公司，获取实时估值数据，评估估值匹配度。

**操作**：

#### 3.1 识别各环节上市公司

使用金融相关skill和搜索每个子环节的相关上市公司：

- 中文搜索："[环节]上市公司"、"[环节]龙头"、"[环节]概念股"
- 英文搜索："[segment] listed companies"、"[segment] leading stocks"
- 研报搜索："[环节]受益标的"、"[主题]投资标的梳理"

将公司按环节分类，标注：
- 公司名、代码、市场（A股/港股/美股）
- 相关业务描述
- 在该环节中的定位（龙头/核心供应商/新进入者）

#### 3.2 获取实时估值数据

使用金融相关skill获取每家公司的以下数据：

| 数据项 | 说明 |
|--------|------|
| PE(TTM) | 滚动市盈率 |
| PB | 市净率 |
| PS(TTM) | 滚动市销率 |
| 总市值（货币） | 按市场货币计价 |
| 营收增速 | 最近报告期同比 |
| 净利润增速 | 最近报告期同比 |


**输出文件**：`相关上市公司.md`

---

### Step 4：交叉验证与交付

**目标**：确保报告数据准确，交付最终成果。

**操作**：

#### 4.1 数据交叉验证

对关键数据点进行交叉验证：
- 估值数据：金融skill vs 网络搜索实时行情
- 市场规模：至少2个来源交叉验证
- 公司业务描述：公司年报/公告 vs 研报 vs 新闻
- 发现矛盾时，以权威来源为准并标注

#### 4.2 报告间一致性检查

- 确保三份报告的环节分类一致
- 确保受益逻辑报告中的环节与上市公司报告一一对应
- 确保估值概览表与各环节估值表数据一致

#### 4.3 交付物

所有文件保存到当前工作区的`./[主题]/`目录：

## 重要规则

### 反幻觉
- 公司业务描述不可凭记忆编造，必须通过搜索验证
- PE/PB等估值数据不可估算或取历史数据替代实时数据
- 市场规模数据必须标注来源和测算日期
- 发现自己不确定的数据，宁可标注"待验证"也不可编造
